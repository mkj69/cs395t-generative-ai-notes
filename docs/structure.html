Information architecture

Text, code, and evidence—
kept in conversation.

The site is organized around research questions rather than lecture dates or file formats. A reader can change views without losing the intellectual thread.

ROOT

A research question

The smallest tension worth preserving.

01

Written note

Intuition, assumptions, derivation, and current understanding.

02

Code + figures

Local scripts, notebooks, outputs, and visual explanations.

03

Evidence

Paper claims, citations, scope, and explicit limitations.

04

Openings

Counterexamples, experiments, and questions that remain live.

01 / RESEARCH THREADS

Maps, not mega-essays.

A thread gives a high-level route through several research units. It records how the central question changes, which evidence creates a branch, and where an experiment challenges the current story.

Current state: structure defined; no research thread published.

02 / RESEARCH NOTES

One note, one real question.

Each note carries its own prose, note-specific code, figures, and data provenance. The page can expose code alongside the claim it tests rather than sending the reader into a detached code dump.

Current state: one blank template; no substantive note published.

03 / EXPERIMENTS

Reproducibility before spectacle.

An experiment gets a question, environment, configuration, expected behavior, result record, and interpretation. Negative outcomes stay visible when they change the reasoning.

Current state: experiment contract defined; no result published.

04 / SOURCE LIBRARY

A claim index, not a PDF drawer.

The library stores bibliographic records, reading notes, and narrow claim ledgers. Original files remain outside the public repository; stable links and provenance connect readers to the source.

Current state: empty bibliography; no paper is represented as read.

A structure should make good judgment easier.

Keep related artifacts close. Keep different kinds of claims distinct.
